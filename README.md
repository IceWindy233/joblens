<h1 align="center">JobLens · 职镜</h1>

<p align="center">在 BOSS 直聘浏览职位时，用你自己的简历档案和你自己配置的大模型，<br>一键生成发给招聘方的打招呼语，同时查看岗位匹配依据。</p>

---

JobLens 是一个 Chrome 侧边栏扩展（Manifest V3）。打开 BOSS 直聘职位页后，它会读取当前职位的 JD，结合你选择的简历档案调用 OpenAI 兼容的模型接口，给出：

- **打招呼语**：围绕岗位关键任务撰写首条招聘消息，可编辑、复制、重写或保存为样例
- **投递参考**：查看 AI 综合评分、投递重点和逐项证据

> [!NOTE]
> 插件**不会**自动发送消息、自动投递或批量操作；所有模型调用都只在你点击按钮时发生。

## 功能特点

- **核心约束与个人偏好分层**：将“真实性、证据边界、结构化输出、数据隔离、不自动发消息”作为不可覆盖的内置约束；内置策略允许主动舍弃次要候选事实并将相同能力领域的项目合并表达；将选材数量、是否使用项目名称/数字/技术细节、是否使用直接匹配判断句、篇幅长度、段落/列表格式、是否解释能力缺口、语气和固定结尾开放为完全可定制的个人规则。
- **三级打招呼语规则与冲突提示**：支持 **全局默认规则 → 档案专属规则 → 单次生成补充要求** 三级配置（优先级：`内置事实与安全约束 > 单次要求 > 档案规则 > 全局默认`），并将 **选材规则（阶段 A）** 与 **写作规则（阶段 B）** 清晰拆分。当同层文字规则与结构化校验参数不一致时，默认以文字规则为准，并在设置页明确标出冲突项支持一键同步或切换。
- **结构化档案事实层**：除人类可读的档案摘要外，支持维护结构化事实清单（事实内容、来源、经历类型、参与程度、技术及能力、成果、限制条件），严格区分个人项目与企业生产经验、已上线与开发中能力。AI 整理生成的事实草稿须经过确认按钮核对后方可保存。
- **多简历档案**：不同求职方向各建一份档案（如“AI Agent 开发”“全栈与研发效能”），每份拥有独立的摘要、事实清单、能力边界说明、规则与历史样例，分析时互不串用。
- **两阶段独立缓存与版本绑定**：匹配分析（阶段 A）与打招呼语撰写（阶段 B）分开缓存并支持零调用缓存复用；阶段 A 缓存额外覆盖选材规则与规范化 JD 内容哈希（即使同一职位 ID 更新了 JD 正文也会自动失效）。匹配分析已过期时禁止基于旧素材单独重写打招呼语；每个打招呼语版本的正文、校验警告与缓存键严格绑定，保护手动编辑内容不被覆盖。
- **本地解析简历**：PDF（pdf.js）/ DOCX（mammoth）在浏览器本地提取文字，支持一键遮蔽手机号、邮箱、身份证号；可用模型整理档案与结构化事实草稿（需用户确认后保存），也可全手动填写。
- **自动跟随职位**：在列表页点选职位或进入职位详情页，侧边栏自动识别当前职位；切换标签页也会跟随。
- **自带模型**：任何 OpenAI 兼容接口（OpenAI、DeepSeek、通义、Moonshot、本地 Ollama 等），需要支持 `/chat/completions`。
- **抗干扰抽取**：自动剔除 BOSS 页面在 JD 中插入的隐藏干扰字，还原形近替换字；薪资如使用字体反爬则留空，不做破解。
- **深色模式与无障碍**：跟随系统自动切换浅色/深色主题，两套配色的文字与控件边界按 WCAG 2.2 AA 对比度设计；侧边栏为生成进度、复制结果和错误提示提供屏幕阅读器播报，开启系统“减少动态效果”时以淡入淡出替代旋转动画。

## 安装

### 方式一：下载发布包（推荐）

1. 在本仓库的 **Releases** 页面下载最新的 `joblens-x.y.z-chrome.zip` 并解压。
2. Chrome 打开 `chrome://extensions`，打开右上角 **开发者模式**。
3. 点击 **加载已解压的扩展程序**，选择解压后的文件夹（里面直接能看到 `manifest.json`）。
4. 安装后会自动打开设置页。

### 方式二：从源码构建

需要 Node.js ≥ 22.12 和 pnpm 11（可用 `corepack enable` 自动启用）。

```bash
pnpm install
pnpm build          # 产物在 dist/chrome-mv3
```

然后按上面的步骤 2–3 加载 `dist/chrome-mv3` 目录。

> [!TIP]
> 更新代码后重新 `pnpm build`，在 `chrome://extensions` 点 JobLens 卡片上的刷新按钮，再**刷新已打开的 BOSS 页面**。

要求 Chrome 116 及以上（侧边栏 API）；建议使用最新版 Chrome。

## 使用

1. **配置模型与全局规则**（设置页 → 模型设置 / 全局默认打招呼语规则）
   - API Base URL：例如 `https://api.openai.com/v1`、`https://api.deepseek.com/v1`；本地服务可用 `http://localhost:11434/v1`。
   - 模型名称、API Key。点击 **保存** 授予该 API 域名访问权限，可点 **测试连接** 验证。
   - 在 **全局默认打招呼语规则** 中可设定跨档案通用的偏好、预设模板及格式/字数校验参数（不会影响岗位评分与差距分析）。
2. **新建或编辑简历档案**（设置页 → 简历档案）
   - 上传文字版 PDF / DOCX，检查提取的文字，可一键遮蔽联系方式。
   - 点 **AI 整理档案与事实** 让模型生成摘要与结构化事实清单草稿，或直接手写；须逐项核对每条事实的“经历类型”“参与程度”与“限制条件”，点击 **我已核对全部事实** 后再保存。
   - 可在 **档案专属打招呼语规则** 中分别配置“选材与岗位重点规则”和“写作表达规则”，展开查看实际生效规则，并支持 JSON 导出/导入。
3. **生成、微调与核对**
   - 打开 BOSS 直聘职位页，点击扩展图标打开侧边栏，选择档案后点击 **生成打招呼语**。
   - **匹配分析（阶段 A）**：按 JD 所要求的岗位级别和责任范围核对档案，区分证据充分、经验可迁移、部分匹配、证据未体现和明确冲突。结果卡显示 AI 综合能力评分和投递重点。在打招呼语下方打开「查看逐项分析」，可核对硬性条件、已有优势、差距和证据覆盖率。
   - **打招呼语撰写（阶段 B）**：根据当前职位的沟通重点和所选事实撰写。点 **依据** 可查看沟通重点与各条素材对应的岗位职责。在 **微调要求** 输入本次写作偏好，点击 **重写** 后应用。需要重新对照 JD 和档案时，点击 **强制重分析**。
   - **本地检查与版本保护**：系统按当前生效规则分别执行结构、事实（数字/年限/边界矛盾）和风格（段落、列表、字数上限和重复邀约）检查，未通过时带具体原因局部重写一次。其中数字检查严格区分候选人事实与职位标题——JD 标题中的年限要求（如“5 年经验”）不能为候选人的年限或成果数字背书。本地检查不能替代全面事实核验，发送前请自行确认真实性；若你已手动编辑草稿，重新生成会放入对比框而不会覆盖当前编辑及其元数据。
   - **缓存刷新说明**：切换模型、JD 正文变化、修改档案事实或修改选材规则后，界面会提示阶段 A 已过期（此时禁止单独重写打招呼语，须先点击 **更新分析**）；仅修改写作规则、临时要求或样例时，只刷新阶段 B。
4. **管理打招呼语样例**
   - 编辑或确认内容真实后，可勾选“设为优先参考”、填写“适用岗位类型标签”并点 **保存为样例**。
   - 生成时优先使用当前职位保存的样例，其次按职位相关性和优先标记选择，最多参考 3 条。第一条决定开场、句子结构、详略和收尾语气，正文经历来自本次选材，并遵循当前写作规则。点 **依据** 可查看本次实际参考的样例。也可在侧边栏或规则参数中关闭历史样例参考。

## 隐私与安全

| 数据 | 存放位置 | 何时离开浏览器 |
|---|---|---|
| 简历档案（含结构化事实）、规则与设置 | `chrome.storage.local`（仅本机） | 点击“整理档案”时，简历文字发送给**你配置的**模型服务商 |
| 当前职位 JD | 正文不持久保存 | 点击“分析”或“仅重新生成打招呼语”时，与档案事实/已选素材及生效规则发送给你配置的模型服务商（**不含**简历原文） |
| 打招呼语样例（含 JD 摘录、标签、候选事实和确认文本） | `chrome.storage.local`，按档案隔离 | 启用样例且点击生成时，仅将样例成稿作为风格参考发送 |
| API Key（默认） | `chrome.storage.session`，浏览器重启后清空 | 仅作为请求头发给你配置的 API 地址 |
| API Key（勾选“记住”） | `chrome.storage.local`，**明文** | 同上 |

- 没有任何开发者服务器、统计或遥测；除了你配置的模型接口，扩展不访问其他网络地址。
- 网页和注入页面的内容脚本都读不到 API Key 和档案；内容脚本只读取当前职位文本，不修改页面。
- “记住 API Key”是明文保存：能访问你电脑上浏览器数据的人或恶意软件可以读取。建议为 JobLens 单独创建一个设置了额度上限的 Key。
- 模型服务商如何处理你发送的数据，取决于该服务商的政策。

## 已知限制

- 目前只支持 **BOSS 直聘**（列表页右侧详情面板与 `/job_detail/` 职位详情页）。页面结构改版可能导致读取失败，侧边栏会提示“职位读取失败”。
- 列表页的薪资通常使用字体反爬，读取为空；详情页一般可读。
- 不支持扫描版 PDF / 图片简历（无 OCR），也不支持 `.doc`。
- 扩展安装或更新后，已打开的 BOSS 页面需要刷新。
- 能力评分由 AI 根据整份 JD 和档案综合给出。证据覆盖率单独统计已有证据的能力主题占比。分数供投递参考，资格、个人工作条件和明确冲突在明细中单独核对。

## 页面改版了怎么办

侧边栏底部的 **诊断 → 导出页面结构** 会导出当前页面的结构骨架（标签、class、可见文字片段、被判定为不可见的元素），以及 JobLens 实际读取到的字段，不需要打开开发者工具。据此更新 [`adapters/boss/selectors.ts`](adapters/boss/selectors.ts) 并补充测试样本即可。快照含页面上的真实文字，分享前请自行检查。

欢迎附上快照提交 Issue。

## Android 客户端（预览）

`android/` 是独立的 Android 客户端：在 BOSS 直聘 APP 中正常浏览职位时，它通过无障碍服务读取当前职位，左侧悬浮按钮显示职位状态。**点按悬浮按钮才会开始分析**：旁边弹出速览卡显示匹配分与结论，同时把打招呼语写入剪贴板并在底部提示，你在 BOSS 中粘贴发送即可；点“查看详情”再展开完整的匹配分析、优势与差距和打招呼语编辑。档案、规则、模型设置与扩展使用同一套界面和分析逻辑。

- 只读：不点击、不滑动、不发送、不截图；离开 BOSS 时悬浮按钮自动隐藏。
- 长 JD 在 BOSS 中默认折叠，悬浮按钮显示 `JD` 时请先点 BOSS 页面上的“查看更多”，展开后自动补全；也可按已读到的内容直接生成。
- 需要开启「JobLens 职位助手」无障碍服务。设置中的“权限与运行”分区（首次打开 JobLens 时直接进入）逐项显示状态并一键跳转：无障碍服务（侧载安装在 Android 13+ 需先在“应用信息”中允许受限设置）、模型与档案、电池优化（小米/HyperOS 上即“省电策略：无限制”）；小米/HyperOS 还需开启自启动并在多任务界面加锁，否则系统会冻结后台的 JobLens，从桌面打开 BOSS 时悬浮按钮不出现。
- 构建：`cd android && ./gradlew assembleDebug`（需要 JDK 17+、Android SDK platform 37、PATH 中有 pnpm）。

架构、边界与真机验证结论见 [`docs/android/ARCHITECTURE.md`](docs/android/ARCHITECTURE.md)。

## 开发

```bash
pnpm dev        # 开发模式（自动打开带扩展的 Chrome，热更新）
pnpm compile    # 类型检查
pnpm test       # 单元测试（Vitest + jsdom）
pnpm check      # 类型检查 + 单元测试
pnpm build      # 生产构建 → dist/chrome-mv3
pnpm zip        # 构建并打包 → dist/joblens-<version>-chrome.zip
pnpm build:android-web  # Android 悬浮面板与设置页 → android/app/src/main/assets/web
```

技术栈：[WXT](https://wxt.dev) · React 19 · TypeScript · pdf.js · mammoth · Vitest。

```
entrypoints/
  background.ts         # 点击图标打开侧边栏；首次安装打开设置页
  content.ts            # 注入 BOSS 页面，只读当前职位（JobState）
  sidepanel/            # 侧边栏：职位、档案选择、分析结果、打招呼语
  options/              # 设置页：模型设置、简历档案管理
adapters/boss/          # BOSS 网页适配：选择器、抽取、变化监听、诊断快照
adapters/boss-app/      # BOSS Android APP 适配：无障碍节点树解析与跨帧合并
analysis/               # 分析 Prompt、结果校验、两阶段分析会话
llm/                    # OpenAI 兼容客户端（超时、取消、错误映射）
profile/                # 简历解析、遮蔽、档案整理与管理
storage/                # 存储封装（默认 chrome.storage，可替换后端）
platform/               # 宿主能力（打开设置、剪贴板、导出、域名授权、文案用语）
shared/                 # 类型、消息契约、错误码、文本工具
mobile/                 # Android WebView 入口：原生桥、悬浮面板、设置页
android/                # Android 原生壳：无障碍服务、悬浮窗、WebView 宿主
tests/                  # 单元测试、DOM 与节点树样本
```

### 发布新版本

1. 修改 `package.json` 的 `version`，提交。扩展 manifest 与 Android 的 `versionName` 都取自这里；Android `versionCode` 按 `主×10000 + 次×100 + 修订` 自动计算（0.3.0 → 300）。
2. 打同名标签并推送：

   ```bash
   git tag v0.3.0
   git push origin main --tags
   ```

3. GitHub Actions 的 **Release** 工作流会校验版本号、运行类型检查和测试，打包扩展并构建正式签名的 Android APK，创建附带 `joblens-<version>-chrome.zip` 与 `joblens-<version>-android.apk` 的 Release（`v0.x` 标记为预发布）。

#### Android 签名密钥（首次发布前配置一次）

```bash
keytool -genkeypair -keystore joblens-release.keystore -alias joblens \
  -keyalg RSA -keysize 2048 -validity 10000
base64 -i joblens-release.keystore | pbcopy   # 复制到剪贴板
```

在仓库 Settings → Secrets and variables → Actions 中添加 `ANDROID_KEYSTORE_BASE64`（上面复制的内容）、`ANDROID_KEYSTORE_PASSWORD`、`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`。缺少任何一项时 Release 工作流会直接失败，不会发布未签名的 APK。密钥库文件请离线妥善备份：丢失后，已安装的用户无法覆盖升级到新签名的版本。

本地构建正式包时设置同名环境变量，并用 `ANDROID_KEYSTORE_PATH` 指向密钥库文件，再运行 `cd android && ./gradlew assembleRelease`；不设置时产出未签名的 release 包。

每次推送到 `main` 或提交 PR，**CI** 工作流都会运行类型检查、测试和打包，构建产物可在该次运行的 Artifacts 中下载。
